# 0.3.3：让短链进入已验证的视频页提取流程

## 用户报告与定位

用户 0.3.2 手机截图及诊断确认：作品 7690790070625783066 在切换原“电脑版”入口后取得 1 个媒体资源，2880 × 2160，页面提供封面、作者、约 4:42 时长。实际最终页面是 m.douyin.com/share/video/7690790070625783066，资源来自 RouterDataParser 和 BrowserState:_ROUTER_DATA。可见 DOM 视频为 0 不影响通过目标绑定的结构化页面数据取得资源。

随后提供的完整分享文案包含短链 5A6uFUxGMFA；手机诊断显示 302 后得到同一编号，普通 HTTP 三入口均没有媒体，报告没有本机网页会话。故不是中文文案或 HTTP 输入不支持，而是普通 HTTP 失败后还需要进入网页提取。开发机对同作品另一短链 bh3WPFYIwso 的匿名请求也返回 302，目标一致；没有根据短链 token 猜测作品。

## 改动

- WebView 仍由用户主动打开，但默认使用 www.douyin.com/video/{id}。正常接受同一作品的 m.douyin.com 跳转，无需先打开 ies 分享页。
- 明确显示「链接已识别，普通请求未取得视频。请点击『用网页继续提取』」。普通网页失败不会冒充链接格式错误。
- 入口按钮称为“视频页入口／分享页入口”；保留设备 WebView 默认 UA，不误称强制电脑模式。
- 诊断记录最多 12 条脱敏网页导航事件；切换页清除上一页的错误观察，旧会话及其他作品回调不能污染当前报告。
- 拾影生成的拦截响应带本机会话标记，在 HTTP 错误回调中排除，避免同一次本机阻止又被算为网站 403。真实未标记的 403/503 仍保留。标记不发往平台，也不写入诊断。
- versionName 0.3.3 / versionCode 6；权限、依赖、资源白名单、解析器接受规则保持原有范围。

## 实测与验证

独立无登录桌面 Chrome 使用与产品相同的初始资源规则、正常浏览器沙箱和证书校验，从视频页入口开始。公开网页自己跳转到 m 分享页，返回目标页面数据；没有直接调用详情 API、伪造签名或导入登录态。脱敏结果在 [v033-live-check.json](v033-live-check.json)。该结果与手机成功记录相符，但不能代替新版 Android 验收。

补充回归覆盖两条用户短链的中文文案、HTTPS/HTTP/无协议形式、重定向标准化、普通提取失败到网页成功的状态流程、本机 403 归类、页面日志限长与过期回调。构建与测试结果：[v033-validation.json](v033-validation.json)。固定捕获脚本本版未改，既有 37 项脚本检查及真实错误页检测证据保留。

Android 回调参考：[WebViewClient](https://developer.android.com/reference/android/webkit/WebViewClient#onReceivedHttpError(android.webkit.WebView,%20android.webkit.WebResourceRequest,%20android.webkit.WebResourceResponse))。本次手机报告中，15 次 HTTP 403 与同源本机阻止逐类对应，结合产品返回合成 403 的实现定位了重复记账问题。

## 尚未完成

这次只完成入口和提示修订；下载器、MediaStore/SAF、通知与完整文件播放验证尚未实现。不保证所有视频均可提取，也不把一个地址或合成回归测试当成下载成功。用户已确认原版有一个成功样本，新版 APK 尚未在此手机上验收。
