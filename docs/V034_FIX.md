# 0.3.4：首次解析自动衔接网页提取

## 问题与行为

用户 0.3.3 报告作品 7691299102264413480：短链 3UxwpV4kkUo 经 302 正确识别编号，三个普通 HTTP 页面返回 200 但没有媒体；用户继续网页提取后，手机已显示封面、作者“鸣潮”、约 22 秒时长及 1 个 1080 × 1920 资源。首次红色提示来自普通请求阶段，页面没有自动进入可用的网页提取流程。

本版默认让一次“解析”或一次系统分享覆盖两个步骤。普通页面缺少媒体、结构暂不能解析或需要正常浏览器验证时，自动打开当前作品视频页入口。中间步骤保持处理中状态，不发出红色最终失败；只有实际得到匹配媒体才成功。

首页开关「需要时自动进入网页提取」默认开启，可关闭并本机持久保存；关闭后保留原手动入口。网络、限流、明确拒绝、登录、删除、无效输入等错误不自动发起额外网页请求。网页可关闭，单次自动回退关闭后不重开；新分享、编辑、取消使旧回调失效。

## 实现

自动切换由当前解析任务的状态转换触发，直接产生浏览器请求，不经过“最终失败”中间状态，也不取消自身任务。手动重开使用新的会话编号，复用现有网页隔离、超时、诊断和清理流程。没有增加网络端点、资源白名单、登录态导入、依赖或权限。

自动开关在接收初始分享前从本机偏好读取，UI 和隐私说明明确网页会产生平台请求及流量。诊断把普通步骤结果留为阶段说明；网页中真实错误仍保留。

## 验证

回归覆盖用户完整鸣潮分享文案的首次按钮解析和系统分享、无瞬时失败状态、关闭不重开、取消/编辑阻止迟到回退、旧请求不能覆盖新视频、请求中关闭自动模式、手动模式及真实网页错误保留。结果见 [v034-validation.json](v034-validation.json)。已有固定脚本与解析器未改，保留之前测试和真实网页证据。

本次没有重新进行平台网页调查；问题由用户日志和截图及现有状态流程确认。开发机 adb 没有连接设备，未宣称新版 Android 真机验收通过。提供可覆盖安装的 0.3.4，versionCode 7，沿用原开发签名。

## 限制

网页成功仍取决于平台是否返回公开媒体。文件下载、MediaStore/SAF、下载通知和完整文件播放验证尚未实现，本版仅修正自动提取流程。
