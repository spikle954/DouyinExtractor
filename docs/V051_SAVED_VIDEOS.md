# 0.5.1 · 保存位置与已保存视频

## 用户问题与最终行为

旧版默认路径是 Download/DouyinExtractor，完成状态下位置仅显示为小字；开始下一条任务会覆盖最近任务界面，用户难以找回上一条文件。

新版完成后突出显示「已保存到」和具体目录，提供「打开保存文件夹」「播放视频」「分享文件」。首页输入框之前增加「已保存的视频」入口，保留最近 50 条成功保存记录，包含文件自己的名称、位置、文件 URI、文件夹 URI、字节数和保存时间。开始新任务、更改目录、退出再打开 App 都不改变这些记录的原始位置。超出条数只移除最早记录，不删除视频文件。

Android 10+ 默认保存到共享 Movies/拾影，写入 MediaStore.Video，使用 IS_PENDING 隐藏未完成文件，发布后交由系统视频库及相册读取。可以通过「文件管理 → 手机存储 → Movies → 拾影」查找，也可在相册中查找「拾影」；厂商相册的显示和刷新时间不同，不能承诺每种手机立即显示同名相册。Android 8/9 继续使用原 SAF 文件夹选择器，自选目录设置继续沿用。

完成后读取系统提供程序实际的 DISPLAY_NAME；默认目录同时读取最终 RELATIVE_PATH，以反映重名文件改名或提供程序调整路径的结果。读取失败则保留本次请求的目录和文件名；不读取其他 App 的媒体或申请存储读取权限。

升级不移动或删除旧文件。旧版最后一次成功下载可进入新记录，原默认位置仍显示 Download/DouyinExtractor，不标成新版目录。更早旧文件没有完整历史可还原，应到原文件夹查找。普通外置存储的文档编号转换为「手机存储」或「存储卷」路径；不把第三方提供程序的内部编号当作文件系统路径，自选提供程序显示授权文件夹名称。

## 打开文件夹的兼容处理

首先用目录文档 URI 尝试 ACTION_VIEW，避免绑定某个厂商或第三方文件管理器。若系统没有支持的处理程序或权限不可用，则改用 ACTION_OPEN_DOCUMENT，以 video/* 筛选本机视频，并通过 EXTRA_INITIAL_URI 指定该记录自己的文件夹。选择视频后交给播放器。不用 ACTION_OPEN_DOCUMENT_TREE 执行浏览，不修改目录偏好、不扩大持久授权。

部分文件管理器可能忽略初始目录；保存位置文字和文件名仍保留供搜索。已移动、删除或授权撤销的文件会给出可操作提示，不宣称文件仍然存在。完成通知显示目录并提供回到拾影查看已保存视频的入口。

这些实现依据 Android 官方的 [共享媒体存储说明](https://developer.android.com/training/data-storage/shared/media)、[系统文件选择器说明](https://developer.android.com/training/data-storage/shared/documents-files) 和 [EXTRA_INITIAL_URI 定义](https://developer.android.com/reference/android/provider/DocumentsContract#EXTRA_INITIAL_URI)。文件夹直接查看是兼容性尝试，系统文件选择器是标准回退。

## 验证与手机检查

新增回归覆盖旧默认目录、未完成/失败任务不进入成功列表、恢复后保留中文文件名/URI/位置/时间/字节数、重复完成去重、50 条限制和畸形记录、手机/外置卷/未知提供程序提示。既有抖音、B 站、分 P 与保存事务回归一并执行。完整 debug/release 编译、单元测试与 lint 结果见 [v051-validation.json](v051-validation.json)。本次没有改动提取策略，没有新增网络媒体下载验证；此前实际下载与播放证据仍见 [v050-live-download.json](v050-live-download.json)。

开发机没有连接 Android 设备或模拟器，因此未完成真机文件管理器跳转与相册验收。手机请检查默认保存后路径和相册、文件夹按钮、连续下载两条后的首页记录、重启 App 和更换目录后的历史位置，并抽查旧版最后一次成功记录。

版本 0.5.1 / versionCode 11，沿用开发签名。没有新增权限、运行时依赖或统计 SDK，媒体直链及其签名仍不持久化。
