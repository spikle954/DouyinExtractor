# 拾影 0.8.4 · 快手可见网页辅助提取

## 问题与判断

用户确认 0.8.3 的第一条极速版分享已经成功，但第二条 K2YNoqJJ（作品 3xie2x2ahb2weu9）仍失败。诊断显示短链 HTTP 302 正确定位；两次作品页 HTTP 200，约 74833 字符，可解析状态为 1，目标作品状态和媒体候选均为 0。用户确认同一条视频在平常的手机浏览器中可以直接播放。

因此失败点在页面没有提供目标媒体，而非无法识别极速版分享。第一条成功且两条都正确识别编号，没有证据表明极速版整体与原版不兼容。开发机使用同一生产原生请求可以取得第二条视频；手机普通请求与浏览器行为差异的具体原因仍未确认，不能把开发机成功当作手机修复通过，也不保证所有公开视频都可提取。

## 行为与实现

保留原生提取优先。快手原生页面缺少目标资源时，按原有自动网页开关进入同一作品的可见官方页面；关闭开关后仅手动进入。抖音网页流程继续原样工作，哔哩哔哩和小红书不进入此流程。页面正常验证由用户手动完成，登录、删除或明确拒绝访问不自动重试；浏览器登录要求会结束当前快手网页提取。

快手入口沿用公开作品页与已验证的固定分享路由，允许切换同一作品官方手机分享入口。BrowserRequest 增加平台类型；回调检查会话、平台、作品编号和当前网页，旧网页结果不能覆盖新分享。浏览器会话继续串行、取消后清理，不将 Cookie 导入原生请求或下载器。

KuaishouBrowserCapture 有界读取页面 HTML、绑定目标的公开媒体字段和 Apollo 缓存。实际桌面网页会把目标字段和引用变为 Vue getter；只读取已知目标媒体字段，未知 getter 和 toJSON 不执行。脚本还观察页面自己发出的公开作品 fetch/XHR 响应，保留原请求及返回值；不制造接口请求、不读取请求头、Cookie、账号字段或签名算法。KuaishouBrowserParser 将快照交给原 SocialPageMapping，沿用 HTTPS CDN 和完整 MP4 校验。不以推荐作品、blob 或未绑定 video 元素作为结果。

初始资源使用审核域名与账号/统计路径过滤，媒体仍经过独立下载校验。WebView 的资源拦截不覆盖全部网络行为。无新权限、运行时依赖、第三方解析器或服务器。原下载、队列、保存、记录格式和 A 版布局保留；首页自动网页说明与隐私文字同步更新。

新增核心测试覆盖作品匹配、域名/协议、动态状态和响应、推荐误匹配、图文、验证/登录及快照大小/嵌套限制；界面状态测试覆盖自动/手动、开关关闭、取消、过期回调和跨平台结果。14 个合成 Node 检查覆盖 Vue 响应式引用、原 fetch/XHR 行为、已知字段读取及边界；既有 37 个抖音脚本检查及原脚本保留。构建、测试和 lint 结果：[v084-validation.json](v084-validation.json)。业务代码范围：[v084-business-preservation.json](v084-business-preservation.json)。合成脚本检查与桌面 Chrome 实测均不代表 Android WebView 运行验证。

## 覆盖安装与手机复测

versionCode 19，沿用包名与开发证书。安装 shiying-0.8.4-debug.apk 覆盖即可，无需卸载；release 用户继续使用同类型签名包。开发机当前无连接的 Android 设备，手机 WebView、验证交互、自动返回和清理仍待确认。

1. 粘贴第二条完整极速版文案，确认普通页面没有媒体时进入可见快手网页；必要时播放，正常手动完成验证，再检查资源。
2. 返回结果后下载并有声播放，再试第一条已成功的极速版分享、普通快手和其他平台。
3. 关闭自动网页开关，确认不自动打开，手动按钮仍可用；关闭网页或粘贴新链接后，旧网页不改变新作品。
4. 仍失败则复制 0.8.4 完整诊断；会包含安全的网页地址、解析步骤与资源计数。之前任务 COMPLETE 与当前提取相互独立。
