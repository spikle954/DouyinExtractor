# 拾影 0.8.5 · 分享入口与验证后播放器数据

## 用户确认与问题

0.8.4 在手机中打开网页后，用户确认分享入口正常手动安全验证后能提取；视频页通过验证能实际播放，但拾影没有取得媒体。新样本来自普通快手，作品 3x5ie2ecghbese4，分享 K75yHRuX。诊断显示原生页面约 75336 字符、目标状态为 0；浏览器只有 HTML 解析尝试，未取得目标状态。出现过的两个媒体网络错误不能解释最终可播放但未提取这一事实。

## 改动

优先进入原分享跳转中已确认、去掉跟踪字段并绑定同一作品的官方手机页；没有合格落点时使用标准官方分享入口。视频页仍是手动备用，切换沿用同一临时会话，不会主动重新清理正在使用的验证结果。抖音原入口与脚本、其他平台原生提取、下载器、资源推荐、队列、记录及目录规则保留。

播放器的动态 videoInfo/info 属性会更新，原全局 Apollo 状态不一定同步。新增有界 Vue 组件读取，严格匹配目标 ID 后，只提取公开媒体字段，不扫描其他作品资源或直接把 blob/video src 当成下载地址。沿用原映射器及 HTTPS/CDN 校验。未知属性、账号、llsid、expTag 和统计字段不读取、不导出。

验证界面的官方 iframe 增加可见性识别，不读取跨域 iframe 文档或验证码内容，不自动完成验证。检测到验证时允许最多 10 分钟连续等待，验证消失后给媒体加载新的 90 秒预算；普通加载保留原上限。快手网页增加系统双指缩放和「缩小网页」，没有修改验证控件、绕过校验或导出 Cookie。缩放参考 Android 官方 [WebSettings](https://developer.android.com/reference/android/webkit/WebSettings)，验证控件的手机实际布局仍待确认。

诊断新增固定摘要：文档加载状态、目标状态、动态作品、详情响应以及可见视频/播放/HTTPS/blob 计数，帮助区分网页播放与媒体读取，不输出媒体地址、查询参数或组件原文。

## 验证与限制

18 个合成 Node 脚本检查通过，包含验证后动态属性、严格目标匹配、未知 getter 不读取、组件循环限制、推荐视频拒绝及官方验证 iframe 显隐。核心与 App 回归、debug/release 编译及 lint 见 [v085-validation.json](v085-validation.json)。原业务范围检查见 [v085-business-preservation.json](v085-business-preservation.json)。

独立桌面 Chrome 以 412 px 宽度、同等资源限制和实际生产脚本访问用户新样本。实际分享入口快照取得 6 个目标资源。为单独验证新增路径，使用真实捕获的组件子集，省略已有 HTML、全局状态及网络响应；生产 KuaishouBrowserParser 从 KuaishouBrowserVideoInfo 取得 6 个资源，并用原 VideoDownloader 完整下载第一个平台提供的资源，共 4687505 字节。独立检查到 720 × 1280 AVC 视频及 AAC 音频；详细轨道、哈希和范围见 [v085-live-browser.json](v085-live-browser.json)。这不是合成媒体，也不是 Android WebView 实机验证。

开发网络中一条 kwaicdn 备选地址在实际 OkHttp 请求时跳到未审核主机，被原下载器拒绝；Node 请求未出现相同跳转。未放宽域名或改推荐，实际完整文件验证使用已提供的 djvod.ndcimgs.com 第一条资源。保留此差异，不把所有资源都标为可下载。

用户已确认 0.8.4 的网页能播放及分享页能提取；0.8.5 的手动验证、动态字段读取、自动返回、缩放和手机保存仍需复测。开发机没有连接 Android 设备，不能将桌面结果宣称为手机修复通过。

## 安装与复测

versionCode 20、原包名和开发证书，覆盖安装 shiying-0.8.5-debug.apk 即可，不卸载。优先重试 K75yHRuX：确认直接进入分享入口，正常手动验证后自动取得资源；下载并有声播放。若想复测备用视频页，切换、验证和播放后点「检查视频资源」，检查新增诊断中的动态作品计数。验证显示不全时尝试缩小网页；仍失败复制新版完整诊断。
