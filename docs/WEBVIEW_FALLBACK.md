# 0.3.1：本机网页辅助提取

## 问题与调整

用户手机实测作品 `7683370277783000950`：短链 302 正确取得作品 ID，三个公开页面均 HTTP 200，但 6 类解析器均没有媒体资源。说明 Phase 2 链接识别工作正常，Phase 3 的匿名 HTTP 无法获得所需数据。

公开移动网页的入口脚本存在客户端加载 `videoInfoRes` 的流程，因此将原定 Phase 5 的基础 WebView 回退提前加入 0.3.1，先验证动态网页的数据。不是因为多写几个解析器就能保证平台返回数据；下载器仍属于尚未完成的 Phase 4。

## 用户可见变化

- 普通提取失败且已识别作品后，出现「用网页继续提取」，必须由用户点击。
- 打开可见的当前作品网页；等待加载、手动点击播放或正常完成验证，再检查资源。
- 可切换同一作品的移动/PC 页面，保留系统 WebView 默认 UA。
- 每 2 秒检查，最多 90 秒，可随时关闭。后台暂停检查和 JS 定时器，但截止时间继续计算。
- 取得匹配资源后关闭浏览器并显示原生信息卡。没有资源时不会假报成功，下载仍不可用。
- 诊断保留最新网页观察，包括加载状态、状态数量、视频元素、HTTPS/blob 来源数量及资源拦截计数。不会保留每次轮询的重复报告。

## 实现边界

固定的只读脚本通过 `evaluateJavascript` 取得受限快照；不使用 JS 原生桥，不读 Cookie 值，不自行请求详情接口或执行签名算法。复用多个网页/JSON 解析器；运行时视频仅接受目标归属清楚、已加载、可确认为渐进式 MP4 的 `currentSrc`。

多个 DOM 视频不能靠“只有一个可见”选择无 ID 的推荐视频；需要明确目标 ID。`blob:`、分轨、HLS/DASH、加密媒体、未知容器和不明归属均不宣称成功。

请求策略使用公开页面调查确认的必要资源主机/路径，阻止已知统计与登录接口。禁止文件访问、权限请求、上传、自动下载、外部应用跳转和 Service Worker 网络，WebView 调试显式关闭。Android 的拦截回调不覆盖所有请求或重定向，不能承诺完全隔离平台网络行为；限制资源可能影响页面运行。详见 [隐私说明](../PRIVACY.md)。

## 数据生命周期

普通 HTTP Cookie 仍只在 OkHttp 内存中；WebView 使用本应用自己的浏览会话，不导入其他 App 的登录态。正常开启前和关闭后串行等待 Cookie 清理，并删除网页存储/缓存。系统组件可能将数据写入本机；异常终止时可能残留，下次打开前再清理，不声称 WebView 是纯内存浏览器。

旧会话、旧页面和编辑前的回调不会覆盖新请求。退出窗口销毁 WebView，释放资源。平台网页本身与平台服务器通信，加载及播放会产生流量。

## 验证结果

`assembleDebug assembleRelease test lintDebug` 通过。

- 194 项不同 JVM 单元测试通过：core 174 + app 20；app 在 debug 和 release 各执行一次，共 214 次测试执行。
- 21 项实际快照脚本的 Node V8 合成 DOM 检查通过。可在项目根目录运行 `node tools/check-browser-capture.mjs`；没有 npm 依赖。
- Android Lint 0 错误、6 条现有依赖更新建议，没有新增权限或 Maven 依赖。
- APK 使用原开发证书，debug 包名不变，versionCode 提升到 4，可覆盖安装。

机器记录：[fallback-validation.json](fallback-validation.json)、[browser-script-validation.json](browser-script-validation.json)。

没有连接 Android 设备/模拟器；当前桌面浏览器 headless 启动受到 Windows GPU 进程访问错误影响。**尚未验证真实 Android WebView 加载、交互验证、手机生命周期或提取成功，不能宣称该作品已可提取。** 合成测试只验证对应代码分支。

## 下一项设备验收

覆盖安装 0.3.1，重新解析同一分享文本，点击「用网页继续提取」。检查实际页面能否加载/播放、正常验证是否可完成、资源能否回到原生界面。失败时关闭窗口后复制诊断，并说明网页显示的提示。若资源仅为 blob，需继续研究与目标绑定的公开页面数据，不把任意网络资源冒充当前视频。
